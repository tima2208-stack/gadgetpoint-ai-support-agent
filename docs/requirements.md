# Требования к AI-агенту поддержки «ГаджетПоинт»

Документ описывает требования к AI-агенту, который берёт на себя первичную обработку обращений в поддержку интернет-магазина электроники. Требования основаны на интервью с руководителем поддержки и на схемах процесса AS-IS / TO-BE.

**Роли:** клиент, AI-агент, оператор 1-й линии, специалист 2-й линии (возвраты и брак), руководитель поддержки.

---

## Функциональные требования

### US-1. Статус заказа

Как клиент, я хочу узнать статус своего заказа в любое время, чтобы не ждать ответа оператора несколько часов.

| № | Дано | Когда | Тогда |
|---|---|---|---|
| а | Клиент указал номер заказа | Клиент спрашивает о статусе | Агент получает статус через API системы заказов и не позже чем через 1 минуту сообщает статус и ожидаемую дату доставки |
| б | Клиент не указал номер заказа | Клиент спрашивает о статусе | Агент запрашивает номер заказа или телефон |
| в | Заказ по указанным данным не найден | Агент проверил систему заказов | Агент сообщает, что заказ не найден, и передаёт обращение оператору 1-й линии с карточкой |
| г | API системы заказов недоступен | Агент пытается получить статус | Агент не выдумывает статус, сообщает клиенту о задержке и передаёт обращение оператору 1-й линии |

### US-2. Доставка, оплата, наличие

Как клиент, я хочу получать ответ про доставку, оплату и наличие в любое время, чтобы не ждать оператора.

| № | Дано | Когда | Тогда |
|---|---|---|---|
| а | В базе знаний есть информация по вопросу | Клиент задаёт вопрос о доставке, оплате или наличии | Агент не позже чем через 1 минуту отвечает, используя только информацию из базы знаний |
| б | В вопросе не хватает данных для ответа (например, не указан товар или город) | Клиент задаёт вопрос | Агент задаёт один уточняющий вопрос и после ответа клиента продолжает обработку |
| в | В базе знаний нет ответа или агент не уверен в нём | Агент обработал вопрос | Агент не выдумывает ответ, сообщает, что подключит специалиста, и передаёт обращение оператору 1-й линии с карточкой |
| г | База знаний недоступна | Клиент задаёт вопрос | Агент сообщает о задержке и передаёт обращение оператору 1-й линии |

### US-3. Возврат или брак

Как клиент, я хочу оформить обращение о возврате или браке без долгой переписки, чтобы быстро получить решение по товару.

| № | Дано | Когда | Тогда |
|---|---|---|---|
| а | Клиент прислал номер заказа, фото товара и чек; заказ найден в системе | Агент проверил данные | Агент формирует карточку заявки, передаёт её специалисту 2-й линии и сообщает клиенту, что заявка передана и когда ждать ответа |
| б | Клиент прислал не все данные | Агент проверяет обращение | Агент запрашивает только недостающие данные |
| в | После двух повторных запросов данные неполные или заказ не найден | Агент проверил данные | Агент формирует карточку со всем, что удалось собрать, передаёт обращение оператору 1-й линии и сообщает клиенту, что подключится специалист |
| г | Система заказов недоступна | Агент пытается проверить заказ | Агент сообщает о задержке и передаёт обращение оператору 1-й линии с собранными данными |
| д | Любое обращение о возврате или браке | Агент общается с клиентом | Агент не обещает возврат денег, обмен или ремонт — решение принимает только специалист |

### US-4. Переход к живому оператору

Как клиент, я хочу в любой момент перейти к живому оператору, чтобы решить вопрос, который мне неудобно обсуждать с ботом.

| № | Дано | Когда | Тогда |
|---|---|---|---|
| а | Клиент явно просит оператора («позовите человека», «хочу оператора») | На любом шаге диалога | Агент прекращает обработку, не уговаривает продолжить с ним, сообщает о передаче и передаёт обращение с карточкой |
| б | Клиент выражает раздражение или недовольство | Агент анализирует сообщение | Агент передаёт обращение человеку и отмечает в карточке тональность «негатив» |
| в | Клиент дважды подряд сообщает, что ответ агента не помог | Агент получает второе такое сообщение | Агент передаёт обращение оператору 1-й линии |
| г | Обращение не относится ни к одному из типов (статус, доставка/оплата/наличие, возврат/брак) | Агент классифицировал обращение | Агент передаёт обращение оператору 1-й линии |

### US-5. Карточка обращения

Как оператор 1-й линии, я хочу получать обращение вместе с карточкой, чтобы отвечать клиенту, не переспрашивая то, что он уже рассказал.

**Поля карточки:**

| Поле | Обязательное | Комментарий |
|---|---|---|
| ID обращения | да | |
| Канал | да | чат на сайте, email, Telegram |
| Дата и время поступления | да | |
| Контакт клиента | да | |
| Тип обращения | да | по классификации агента |
| Тональность | да | нейтральная / негатив |
| Причина эскалации | да | из фиксированного списка (см. критерий «б») |
| Краткое резюме проблемы | да | не более 3 предложений |
| Что агент уже ответил клиенту | да | |
| Полная история переписки | да | |
| Номер заказа и статус | нет | если были получены |
| Вложения (фото, чек) | нет | если были получены |

| № | Дано | Когда | Тогда |
|---|---|---|---|
| а | Обращение передаётся человеку | Агент формирует карточку | Карточка содержит все обязательные поля; необязательные — если данные были получены |
| б | Обращение передаётся человеку | Агент заполняет причину эскалации | Причина выбрана из списка: просьба клиента / негатив / нет ответа в базе знаний / заказ не найден / данные не собраны / сбой системы / нестандартный вопрос |
| в | По обращению уже создана карточка | Клиент пишет повторно | Сообщение добавляется в ту же карточку и попадает тому же сотруднику, новое обращение не создаётся |
| г | Агент формирует резюме | — | Резюме не длиннее 3 предложений и содержит только факты из переписки |

> Критерий «в» закрывает проблему из AS-IS: повторное сообщение клиента попадало к другому оператору, и контекст терялся.

### US-6. Обращения в нерабочее время

Как клиент, который пишет ночью, я хочу знать, когда мне ответит человек, чтобы не ждать вслепую.

| № | Дано | Когда | Тогда |
|---|---|---|---|
| а | Обращение требует человека, время вне 9:00–21:00 | Агент передаёт обращение | Агент сообщает клиенту, что специалист ответит после 9:00, и ставит карточку в очередь |
| б | В очереди есть ночные обращения | Наступает 9:00 | Операторы получают ночные обращения первыми, в порядке поступления |
| в | Ночью клиент задаёт типовой вопрос (статус, доставка, оплата) | Агент обрабатывает вопрос | Агент отвечает сразу, как днём: ночной режим касается только передачи человеку |
| г | Ночью собрана полная заявка на возврат | Агент передаёт заявку | Заявка ждёт специалиста 2-й линии в очереди, клиенту сообщается срок рассмотрения |

## Нефункциональные требования

| № | Категория | Требование |
|---|---|---|
| НФТ-1 | Скорость | Ответ агента на типовой вопрос — не более 1 минуты для 95% обращений |
| НФТ-2 | Доступность | Агент принимает и обрабатывает обращения круглосуточно |
| НФТ-3 | Достоверность | Агент отвечает только на основе данных из системы заказов и базы знаний; если данных нет — передаёт человеку, а не догадывается |
| НФТ-4 | Персональные данные | Агент запрашивает только данные, нужные для решения вопроса; не запрашивает данные банковских карт и паспорта |
| НФТ-5 | Тон общения | Вежливо, на «вы», без обещаний, которые может дать только сотрудник |
| НФТ-6 | Измеримость | Каждое обращение логируется: тип, время первого ответа, решено ли агентом, причина эскалации — для расчёта метрик |

---

## Допущения

1. В MVP информация о наличии товара берётся из базы знаний. Наличие меняется постоянно, поэтому в следующей версии его нужно получать через API склада (вопрос вынесен на согласование с заказчиком).
2. Система заказов предоставляет API для получения статуса заказа по номеру заказа или телефону.
3. Обращения из всех каналов (чат, email, Telegram) поступают в единую точку входа.

## Трассируемость: требования ↔ схема TO-BE

| Требование | Элемент схемы |
|---|---|
| US-1 | Подпроцесс «Сообщить статус заказа» |
| US-2 | Подпроцесс «Ответить по базе знаний» |
| US-3 | Подпроцесс «Собрать данные по возврату», шлюз «Данные собраны?», дорожка «Специалист 2-й линии» |
| US-4 | Шлюзы «Нужен человек?» и «Вопрос решён?» |
| US-5 | Задача «Сформировать карточку обращения», объект «Карточка обращения» |
| US-6 | Шлюз «Рабочее время?», таймер «Наступило 9:00» |
